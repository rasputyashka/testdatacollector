# Data Collector

Локальный приёмник системных метрик: **FastAPI + Jinja2 + SQLite**. Совместим с соседним [data-sender](../data-sender/README.md), без изменения агента. Python 3.11+.

## Запуск

Из корня репозитория:

```bash
cd data-collector
```

```bash
python3 -m venv .venv
```

```bash
.venv/bin/python -m pip install -r requirements.txt
```

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Интерфейс: <http://127.0.0.1:8080/>. БД создаётся автоматически в `data-collector/data/collector.sqlite3`; данные сохраняются между перезапусками. Шаблоны и CSS находятся относительно пакета, а не текущего каталога.

**Авторизации нет.** По умолчанию сервер слушает только loopback. Не публикуйте его в интернет или недоверенную сеть: UUID хоста не удостоверяет отправителя. CORS выключен, Host ограничен локальными именами. Для сетевой эксплуатации нужна отдельная защита как интерфейса, так и приёма отчётов.

## Отправка данных

В другом терминале, из корня репозитория:

```bash
cd data-sender
```

```bash
python3 workload_collector.py --config config.toml --state-dir .state
```

Первый отчёт отправляется сразу, следующие — каждые 60 секунд. Адрес в настройках агента уже совпадает с адресом приёмника. Агент записывает свой UUID в каталог состояния; подробности — в его README.

## Интерфейс

- `/` — поиск по имени/UUID, страницы по 25 хостов и последние метрики.
- `/hosts/{host_id}` — последний по времени **сбора** отчёт, диски, сеть и история по 25 записей.
- `/reports/{id}` — экранированный просмотр полного JSON.
- `/api/v1/reports/{id}` — JSON сохранённого отчёта.
- `/healthz` — проверка чтения SQLite (`200` или `503`).

Обновление вручную. Статус «Свежие данные» означает, что отчёт получен недавно, а не что хост гарантированно доступен. Метрики `null` отображаются как «Нет данных», пустые массивы — как отсутствие элементов, нулевой swap — как неиспользуемый swap.

RAM рассчитывается как `(total − available) / total`. Сетевые счётчики накопительные; скорость рассчитывается по двум соседним отчётам в порядке времени сбора. Она неизвестна для первого замера, отсутствующего интерфейса, неположительного интервала, уменьшения счётчиков или смены двух известных boot ID. Отсутствующий boot ID сам по себе не считается перезагрузкой. Интерфейсы не суммируются. Значения объёмов показаны в двоичных единицах (КиБ, МиБ, ГиБ).

## Контракт приёма

`POST /api/v1/reports` (без завершающего слеша), `Content-Type: application/json`, без сжатия. Одно тело — один отчёт схемы 1. Поля описаны в [документации отправителя](../data-sender/README.md#формат-отчёта). UUID и дата с часовым поясом обязательны; числовые счётчики неотрицательные, CPU 0–100. Дополнительные поля допускаются и сохраняются, стандартные nullable-поля обязательны даже при `null`.

- `204 No Content` — транзакция SQLite успешно зафиксирована.
- `422` — неправильный JSON или схема (включая NaN/Infinity).
- `413` — тело превышает лимит, в том числе при потоковой передаче без Content-Length.
- `415` — неподдерживаемый тип содержимого или сжатие.
- `503` — ошибка SQLite, успешный приём не подтверждён.

Редиректов для нормализации завершающего слеша нет. Дубли сохраняются отдельно; при равных временах сбора последним считается отчёт с большим внутренним ID. Пришедший с опозданием отчёт остаётся в истории, но не заменяет более новые метрики. Время последней связи обновляется независимо.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `COLLECTOR_DATABASE` | `data-collector/data/collector.sqlite3` | Путь к БД (относительный путь считается от рабочего каталога) |
| `COLLECTOR_STALE_SECONDS` | `180` | Возраст связи для статуса давности |
| `COLLECTOR_MAX_BODY_BYTES` | `1048576` | Максимум байтов JSON |
| `COLLECTOR_ALLOWED_HOSTS` | `localhost,127.0.0.1,[::1]` | Допустимые Host через запятую |

Для другого хранилища, из `data-collector/`:

```bash
COLLECTOR_DATABASE=/tmp/collector-demo.sqlite3 .venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8080
```

Встроенный предпросмотр из `.claude/launch.json` использует порт `8081` и отдельную демонстрационную БД `/tmp/testdatacollector-preview.sqlite3`, не основное хранилище. Для отправки туда задайте агенту URL с портом `8081` в его настройках либо используйте curl.

Один Uvicorn worker достаточен для локального использования. SQLite использует WAL и 5-секундное ожидание блокировки. Держите БД на локальном диске, не в сетевой файловой системе.

**Автоматической очистки истории нет:** БД растёт с каждым отчётом. Следите за свободным местом. Для резервной копии остановите сервер перед копированием БД и её WAL/SHM-файлов либо используйте SQLite backup API; простое копирование работающей БД без WAL может потерять подтверждённые записи. Сервер не устанавливает службы и ничего не удаляет.

## Тесты

Из `data-collector/`:

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
```

```bash
.venv/bin/python -m pytest -q
```

Тесты используют временные БД, TestClient и настоящий loopback HTTP для проверки штатного `send_report()`. Пользовательские данные и службы не меняются.
